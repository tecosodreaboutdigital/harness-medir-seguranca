Agent skills

The harness, written for the machine to follow

A skill is not a shortcut to give an agent more power. It is the harness in a form the agent can follow: what it may do, what it never does and who confirms.

On this page

  1. Format and installation
  2. The seven skills
  3. Security review for integrations

Format and installation

The skills follow the open Agent Skills format: one folder per skill, with a SKILL.md file that starts with name and description in YAML. Any agent that supports the format can load them. Instructions are in Portuguese, with a short English summary at the top of each file.

  1. Open the repository's skills/ folder and read the whole SKILL.md. A skill you have not read is an unknown instruction running inside your agent.
  2. Copy the skill folder into your agent's skills directory (in Claude Code, for example, .claude/skills/ in the project).
  3. Test with a fictitious alert before any real data.
Mandatory section

Every skill in this repository has a harness section with three lines: what it may do, what it must never do and who confirms. A skill without that section does not get in.

The seven skills

mapear-camera

Map step · interview and contract

Interviews the user about one camera, one event and one decision. Returns a filled task contract, the control level and the table row that set it. Whatever the user does not know becomes an open item with an owner, never a guess.

Mayask, draft, apply the table, mark open items
Neverinvent answers, lower the level to save time, accept real personal data
Who confirmsthe person who owns the contract

Read the skill

triagem-de-alerta

Equip step · the prompt with harness, made permanent

Takes an alert and answers in the A to E format, in 120 words or fewer: hypotheses including a false positive, what to check in 60 seconds, who decides, what to log, what it does not know. It reads the case's control level and the data integrity seal.

Maypropose hypotheses, checks and the log text
Neverdecide, or recommend anything hard to undo without confirmation on video
Who confirmsthe operator; at N3, another person authorizes

Read the skill

revisar-nivel-de-controle

Delegate and Inspect steps · audit

Audits an operation with analytics already running: rebuilds each case's sentence, applies the table, compares it with the declared level, runs the checklist and returns the gaps by severity, starting with Lock cases running automatic actions.

Mayread, ask, classify and point out gaps
Neverchange configuration, "approve" the operation, blame the operator
Who confirmsthe control room lead, one open item at a time

Read the skill

integracao-vms

Equip step · video management system, read-only

How to bring alerts from the video management system to the assistant through ONVIF events, REST or a signed webhook, with no path back. Includes a fictitious ONVIF message, a webhook payload and a Python mock server (standard library only) that checks HMAC and timestamp, rejects replays and drops fields outside an allowlist.

Mayreceive, verify, normalize and store events for reading
Nevermove cameras, export or delete recordings, change analytics rules
Who confirmsthe system owner approves credentials and scope; the operator, each action

Read the skill and examples

integracao-controle-de-acesso

Equip step · access control and HR, read-only

Read-only webhook for events such as credential revoked, employee offboarded and attempt with a revoked credential, with people identified only by a pseudonymous id. Includes notes on Brazil's data protection law (LGPD) for biometrics: sensitive data (art. 11), legal basis, retention, records and audit.

Mayreceive events, alert the operator, open a removal task
Nevergrant, block, create or delete credentials or biometric records
Who confirmsthe operator on video; the administrator removes; the data protection officer sets basis and retention

Read the skill and examples

saude-da-operacao

Inspect step · data integrity seal

Health signals (Zabbix, SNMP, ping, HTTP, recording status, clock) become a seal on every number and every alert: intact, estimated, late or no data. The worst seal wins, zero only shows with an intact seal, and an infrastructure failure never shows as "nothing happened".

Mayread signals, compute the seal, alert, open a maintenance ticket
Neverrestart equipment, silence problems, show zero without data
Who confirmsthe operator routes it; maintenance confirms cause and repair

Read the skill and example

mcp-central

Equip and Delegate steps · MCP server design

A design document for an MCP server with three tools: consultar_alerta (read an alert), abrir_chamado (open a ticket) and pedir_trecho_de_video (request a video clip). Each one has a scope, a rate limit, a confirmation rule, an audit entry and errors that say what to do next. N3 actions are left out on purpose: the safest tool is the one that does not exist.

Mayguide design, review and implementation
Neverpropose irreversible tools or confirmation by the model itself
Who confirmsthe operator, in the console; the control room lead approves any new tool

Read the design

Security review for integrations

The skills that touch systems (video management, access control, operational health and the MCP server) share the same minimum review. Every "no" is an open item with an owner, before go-live.

  • Authentication on every channel; nothing anonymous.
  • Least privilege: credentials read only what the case needs.
  • Read-only by default; writing to a third-party system is a recorded decision and raises the level.
  • Secrets out of the repository, in environment variables or a vault, with rotation.
  • Logs without personal data: id, type, time and result; never images, faces, plates or names.
  • Rate and size limits, with errors that say what to do.
  • Replay protection on webhooks: HMAC-SHA256 over timestamp and body, a short window, duplicate ids rejected.

All examples use exemplo.local hosts, test secrets read from environment variables and no data from real systems.
