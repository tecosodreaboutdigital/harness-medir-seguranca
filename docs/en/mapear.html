Step 1 of 5 · M

Map

Which task, at what risk? "We want AI on the cameras" is not a task. One camera, one event and one decision is.

What it is for

Map is where the control level gets decided, before any conversation about tools, models or vendors. The unit is always the same: one camera, one event, one decision.

Without that scope, no later sensor can tell whether the AI got it right, because nobody said in advance what right looked like. And the night-shift operator ends up receiving alerts from a system nobody knows how to judge.

Questions

  1. Which camera (or group of cameras with the same scene), which event, and which decision will the alert feed?
  2. Who makes that decision today, without AI, and how fast?
  3. What does a false positive cost? And a false negative? In people, operator time, money, reputation.
  4. How many times a month does the event happen, and how many alerts a month do you expect?
  5. What must never happen, even if the AI is right? (stopping the wrong person, blocking an emergency exit, halting a production line)
  6. When the alert fires, does someone act in the real world in a way that is hard to undo?
  7. Does the system need to read from or write to another company's or the client's system?
  8. Is there a way to check whether the alert was right? (second sensor, recorded video, check on site)
  9. Out of every thousand alerts, how many false ones will you accept before reviewing the system?
Shortcut

Questions 4, 6, 7 and 8 set the control level. See the four questions and the full table.

What comes out

  • The use case in one sentence.
  • The control level and the table row that set it.
  • The false-positive target per thousand alerts, agreed before go-live.
  • The list of things that must never happen.
  • A filled-in task contract, with gaps marked as open items.

Anti-patterns

  • Mapping the product instead of the task. "Let's turn on perimeter analytics on every camera" is not a use case. Each scene has a different cost of error.
  • Skipping the cost of a false positive. If nobody knows what a false alarm costs, the target becomes an opinion once the system is already live.
  • Letting the vendor set the level. "This system is N1" does not exist. The same equipment can be N1 in one scene and N3 in another.
  • Leaving "must never happen" implicit. Whatever is not written down will be discovered in operation, the hard way.
  • Mapping without asking the operator. Whoever spends eight hours in front of the video wall knows how many useless alerts already come in.
